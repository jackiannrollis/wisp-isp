# Drill record: A, FreeRADIUS node outage (local rehearsal)

The first run of drill A, on the local test stack (`infra/stack/test.sh`, the same compose file and monitoring project as a host), while the runbook was written. It stands in for a staging record until staging exists; the probe timer was replaced by running `probes radius` by hand every minute.

| | |
|---|---|
| Date and window (UTC) | 2026-10-26, 10:53 to 11:08 |
| Inventory and host | local test stack (`corebalt.localhost`), Docker Desktop on Windows |
| Operator, witness | the session; no witness |
| Release deployed (`stackctl status`) | `stacktest-1` |
| Tenants informed (production) | not applicable |

## Baseline

- Alerts firing before the drill (besides the Watchdog): `CorebaltCertificateExpiring` and `CorebaltCertificateExpiringSoon` for the three local names (Caddy's internal CA issues short certificates; expected locally only).
- Sessions before: none (no router is peered with the local stack).
- Login check before (the drill line `CB000001` of the lab seed): accepted at 10:51 after `stackctl reload-radius`.

No notification could be received: the local Alertmanager has no receiver (the test writes `receiver: none`).

## Result

- Sessions after: none, as before.
- Expected effects seen: the probe reported the service down within a second; the alert went pending at the next evaluation and fired after its 5-minute window plus one evaluation; it resolved within one probe and one evaluation of the restart; a login was accepted afterwards.
- Unexpected: nothing.
- Passed against the criteria of `../failover-drill.md` for drill A on a single node (fired within 7 minutes of T0, resolved within 3 minutes of T1, login accepted), except the notification delivery, which the local stack cannot show.
